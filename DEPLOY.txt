DEPLOYMENT — feat/deploy

Vercel hosts the mobile app UI only. Deploying the UI does not move the
Chrome extension worker off the Mac and does not provide access to 10.10.x.x.

Vercel setup:
- Import this repository, select feat/deploy for a preview deployment.
- Framework: Other. Root directory: repository root.
- No build command; output directory: mobile-app (set in vercel.json).
- Deploy the already generated public assets; no Supabase PAT, bot token,
  history token, password or secret environment variables are needed.
- Keep the existing production branch and GitHub Pages deployment unchanged.
- Existing login links point to GitHub Pages. On a Vercel preview, use the
  password login already configured for this app; sessions are per origin.

Always-on processing requires a separate machine/server running the extension
and authenticated OpenSIPS/FreeSWITCH tabs, with access to the internal network.
A cloud server needs its own VPN/private route that stays up without the Mac.
Do not start a second active worker against production while the Mac controls it.
Use a separate test backend before validating any new worker implementation.

This branch prepares hosting only. No production deployment, database change,
worker migration or live FreeSWITCH/OpenSIPS action has been performed.

Repeatable preview upload:
  python3 scripts/deploy-vercel.py --dry-run
  python3 scripts/deploy-vercel.py --project <existing-project-id-or-name>
  Add --team-id <team-id> for a team-owned project.
The token is read locally from ignored vercel_key.md; only allowlisted public
assets are uploaded. The script never deploys a production target.
